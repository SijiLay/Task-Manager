# Version History

This document explains how the Task Manager project developed across each version. Each version focused on improving a specific part of the program, starting from basic task management and ending with documentation and GitHub professionalization.

---

## V1: Basic Console Task Manager

The first version focused on creating the basic task manager idea. The program allowed the user to add tasks, view tasks, complete tasks, delete tasks, and exit the program.

### Main Focus

- Create a working console menu
- Store tasks in memory
- Allow basic task actions
- Practice Java classes, methods, conditionals, loops, and user input

### Result

By the end of V1, the project worked as a basic task manager, but it still needed stronger input validation, cleaner code organization, and permanent saving.

---

## V2: Input Validation and Error Handling

Version 2 focused on making the program safer and more user-friendly. The goal was to prevent the program from crashing when the user entered invalid input.

### Main Focus

- Validate menu choices
- Prevent crashes from letters when numbers were expected
- Handle empty task names
- Handle invalid task numbers
- Handle actions when no tasks existed

### Result

By the end of V2, the program became more reliable and easier to use.

---

## V3: Code Organization

Version 3 focused on improving the structure of the project. Instead of keeping all logic in one place, responsibilities were separated across different classes.

### Main Focus

- Separate task data from task logic
- Move task operations into a manager class
- Make the project easier to read and expand

### Result

By the end of V3, the project had a stronger object-oriented structure.

---

## V4: File Saving and Loading

Version 4 added file persistence so tasks would not disappear after the program closed.

### Main Focus

- Save tasks to a text file
- Load saved tasks when the program starts
- Practice Java file reading and writing
- Make the app feel more realistic

### Result

By the end of V4, tasks could persist between program runs.

---

## V5: Task Editing

Version 5 expanded what users could do with existing tasks.

### Main Focus

- Rename tasks
- Mark completed tasks as incomplete
- Improve task update options
- Give users more control over their task list

### Result

By the end of V5, the task manager became more flexible and useful.

---

## V6: Priority and Category Organization

Version 6 focused on making tasks more organized by adding priority and category fields.

### Main Focus

- Add task priorities
- Add task categories
- Display more task information
- Save and load the new task data

### Result

By the end of V6, tasks were easier to organize and understand.

---

## V7: Refactoring and Navigation Improvements

Version 7 focused on cleaning up the code and improving the program flow.

### Main Focus

- Reduce repeated validation code
- Add helper methods
- Improve menu navigation
- Make `Main.java` cleaner
- Add reusable display methods
- Improve search, filter, and sort result displays

### Result

By the end of V7, the project was cleaner, easier to maintain, and easier to expand.

---

## V8: Portfolio Documentation and GitHub Professionalization

Version 8 focused on making the project ready to show on GitHub. This version was not programming-heavy. The main goal was to improve the way the project is presented.

### Main Focus

- Write a professional README
- Add project documentation
- Explain the version history
- Clean up the repository
- Prepare the project for a portfolio
- Make the project easier for others to understand

### Result

By the end of V8, the project became more polished, professional, and ready to share.
